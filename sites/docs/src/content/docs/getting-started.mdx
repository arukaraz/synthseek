## Before you begin

You need two things.

- **Docker and Docker Compose**, on a machine that stays on.
- **Two folders**: one where your download clients put completed downloads, and one where your organised music library lives. Synthseek reads from the first and writes to the second.

A running slskd instance is optional. It is the peer-to-peer source: slskd is what actually performs those downloads, and Synthseek drives it through its web API, which must be reachable from the Synthseek container, and never speaks the Soulseek protocol itself. Without it, Synthseek downloads through the other sources you turn on. Full setup is on the [Download Sources page](/download-sources).

An AcoustID key is optional but strongly recommended. Without one, Synthseek cannot verify by listening that a downloaded file is what you asked for. It is free and takes a minute to obtain.

## Installing with Docker Compose

Create a `docker-compose.yml`:

```yaml
services:
  synthseek:
    image: ghcr.io/arukaraz/synthseek:latest
    container_name: synthseek
    restart: unless-stopped
    ports:
      - "4400:4400"
    volumes:
      - /path/to/synthseek/data:/data
      - /path/to/your/music:/music
      - /path/to/slskd/downloads/complete:/downloads
    environment:
      - PUID=1000
      - PGID=1000
      - AUTH_SECRET=replace-with-a-long-random-string
    healthcheck:
      test: ["CMD-SHELL", "wget -q --spider http://localhost:4401/api/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 60s
```

Generate the auth secret with:

```bash
openssl rand -base64 48
```

Then start it:

```bash
docker compose up -d
```

Open `http://your-server:4400`.

Your slskd address and API key are not set here. First-run setup collects them and stores them in the database, along with everything else you connect.

### What each volume is for

| Container path | What goes there                                                                                                             | Notes                                                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/data`        | The database, configuration, logs, artwork cache, backups, drop-import staging, files held for review, and the recycle bin. | Back this up. Everything Synthseek knows lives here.                                                                                                   |
| `/music`       | Your organised music library. Synthseek writes here.                                                                        | Can be mounted read-only, in which case Synthseek boots and browsing works, but imports and any reorganising of the library fail until it is writable. |
| `/downloads`   | The folder your download clients write completed downloads to.                                                              | Must be writable. This is the same folder slskd calls its "complete" directory.                                                                        |

### Ports

| Port   | What it is                                                                                                  |
| ------ | ----------------------------------------------------------------------------------------------------------- |
| `4400` | The web interface. Change with `WEB_UI_PORT`.                                                               |
| `4401` | The internal API. Fixed inside the container, used by the health check. Not something you normally publish. |

### PUID and PGID

Synthseek runs as an unprivileged user inside the container. It takes ownership of its own `/data` volume at boot and never touches the ownership of your music and downloads folders. Set `PUID` and `PGID` to the user and group that own your downloads and music folders on the host.

If the downloads or music folder is not usable, Synthseek still starts, and downloads wait until it is fixed. The container log names the offending path and the ownership fix, and admins see the same under **Settings**, **Maintenance**, **System status**. A music library that is readable but not writable holds nothing back: browsing works, and imports into the library fail until you fix the ownership.

## First run

The first time you open Synthseek, setup asks you four questions, one per screen.

1. **Your account.** Create the first account. This account is the instance owner and cannot be demoted or deleted. It is the only question you cannot skip.
2. **Where your music plays.** Pick Plex, Navidrome or Jellyfin, then connect it. Plex opens a popup to sign in at plex.tv and lets you pick a server. Navidrome asks for an address and a login, and Jellyfin for an address and an API key. Both are tested before you continue. Choose none if you have no server yet.
3. **How new music arrives.** Enter the URL and API key of your slskd instance. Synthseek tests the connection and tells you what it found. You can continue past a failed test, and Synthseek will boot anyway and show the integration as unhealthy so you can fix it from Settings.
4. **A contact email for MusicBrainz.** MusicBrainz asks every app to identify itself, and without an email your lookups share a slower limit. The other enrichment keys are added later, from Settings.

### The setup token

The account question asks for a **setup token** first. The server writes it to its log each time it starts while no account exists. Read it from the container log, for example with `docker logs synthseek`, and paste it in. Each start prints a new one, and repeated wrong tokens are refused for a while. If you set the `ADMIN_MIGRATION_*` variables described under [Configuration](/configuration#one-shot-migration), the account comes from them and there is no token.

### Skipping, and what comes after

Every question except the first can be skipped, and you can go back to an earlier one before you finish.

An administrator's board then shows a **Finish setting up** card for what is still unset: a media server, a download source and the MusicBrainz email. Each item links to its place in Settings, and **Hide for now** removes the card. It appears only on a server where at least one of these questions was answered or skipped.

The sign-in and setup screens have an **Accessibility** link that opens a shorter set of the options under [Settings, Accessibility](/configuration#accessibility).

Every value you enter lives in the database and can be changed later from Settings. Nothing is written to a configuration file you would have to edit by hand.

## Your first request

1. Go to **Search** and type an artist, a song, an album, or a mood.
2. Pick a result. A song opens a request window. An album or a playlist opens its page, where **Request** requests it with your request preset. For trusted members and administrators, its right half opens the request window.
3. In the window, optionally change the format, the bitrate, and how strictly each should be matched. It starts from your preset, and a plain member sees the preset without changing it.
4. Confirm.

The request appears on the **Requests** screen straight away. You will see each track move through searching, downloading, and importing, live. When it finishes, the tracks appear in your **Library**.

If you requested a playlist, the request is accepted immediately and the tracks fill in behind it. A progress dock in the corner keeps you posted while that happens.
