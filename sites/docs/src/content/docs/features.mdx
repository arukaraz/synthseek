## Search and requests

Search covers tracks, albums, artists, and playlists from the connected music catalog. It understands more than exact titles: a query like "workout energy" or "chill sunday" is routed to genre and mood browsing rather than plain-text search.

Every request opens a window where you can set, per request:

| Option               | What it does                                                                     |
| -------------------- | -------------------------------------------------------------------------------- |
| Format               | The audio format you want: mp3, flac, aac, m4a, ogg, wav, or opus.               |
| Format matching      | Strict accepts only that format. Flexible accepts near equivalents.              |
| Bitrate              | A target between 128 and 320.                                                    |
| Bitrate matching     | Strict holds out for the target. Flexible falls back through lower tiers.        |
| Minimum upload speed | Skip peers slower than this.                                                     |
| Require a free slot  | Only consider peers that can start immediately.                                  |
| Sources              | Which sources to try and in what order, or hand the request to Lidarr instead.   |
| Name                 | For playlists, an optional name so it lands in your library the way you want it. |

These choices are stored on the request itself, so a retry weeks later still honours what you originally asked for.

### The requests screen

Requests are grouped by album and playlist, with a sidebar of groups and a detail panel for the selected one. The list is ordered by most recent activity, so anything you just asked for, or that just changed, is at the top. Each row shows when it was requested and when it last moved.

From here you can retry a failed track, retry a whole group, cancel anything in flight, delete a request, prioritise it, or pause it.

## The download queue

Downloads run one album or playlist at a time, in order. Every track in a group finishes before the next group starts, so you never end up with five half-finished albums.

- **Jump the queue.** Move any track, album, or playlist to the front from its actions menu. A badge shows it took effect. Retried tracks are prioritised automatically.
- **Pause and resume.** Pause an individual album or playlist, or the entire queue, from the toolbar. A paused album or playlist stays parked until you resume it, including across a restart. Pausing the whole queue lasts until you resume it or the container restarts.
- **Restart recovery.** If Synthseek restarts mid-queue, it rebuilds the queue from the database on boot and picks up where it left off. Paused work stays paused, and work already handed to Lidarr is left alone.

## Verified imports

Synthseek checks what arrived before it goes into your library.

- The file's tags are checked against what you asked for, and a file that does not match closely enough is refused.
- With an AcoustID key configured, the audio itself is fingerprinted and identified, so a file whose tags look right but whose audio is by a different artist is refused. An identification that comes back inconclusive does not block anything; only positive evidence against the file does.
- A file whose tags cannot be read at all is refused rather than waved through.

A refused file is not thrown away.

### The review queue

Anything that failed verification waits in a review queue. For each held file you can see exactly why it was rejected, listen to it, and then approve or discard it. Approving imports it immediately. Discarding removes the file and leaves the rejection on record.

Held files are kept for a configurable retention period, fourteen days by default.

### Source quarantine

When a source repeatedly delivers the wrong thing, that exact source and file pairing is quarantined and excluded from future searches. Other files from the same peer stay eligible; quarantine is deliberately narrow. You can see which sources have been set aside and why, and lift a quarantine at any time.

Separately, and off by default, peers can be automatically banned after a configurable number of failed attempts.

## Automatic retries

Anything Synthseek could not find can be watched. A background sweep re-searches watched tracks on a cadence that spaces attempts out as a track stays missing, so a brand new release is retried sooner than something that has been unavailable for months.

Under a failed track you can see when the next attempt is due, how many attempts there have been, and start one immediately.

A track that failed because of a problem on your own machine, a full disk or an unwritable folder, does not spend any of its retry budget. That is not something another peer can fix, so Synthseek keeps waiting for you rather than quietly giving up.

This is off by default.

## Quality upgrades

Already have a song in poor quality? Ask for a better copy and Synthseek replaces it in place.

- The decision reads the actual files, not search result metadata, so a claimed bitrate cannot fool it.
- The old file is moved to a recycle bin rather than deleted, and the move is verified before anything else happens.
- If the replacement cannot be completed, the original is restored where possible, and otherwise waits in the recycle bin with a **Restore** beside it, and the log names exactly where it is.
- The recycle bin empties itself after a retention period, thirty days by default.

You can upgrade a single track, or select several tracks in your library and upgrade them in one action. Synthseek reports back honestly on each one.

## Bring in music you already have

Drag your own files into Synthseek, including zip archives. Each track is identified, tagged, and filed into your library the same way a download would be. If a file matches something you had already requested, that request is closed out for you.

Uploads are streamed rather than buffered, so large archives work. Archive contents are validated before extraction.

## Your library

A full library section to browse everything you have.

- **Tracks** is a table, with sorting, per-column filters, and a requested-at column.
- **Albums**, **Artists**, and **Playlists** are card grids with artwork.
- Faceted filtering across all views, with counts that respect the other active filters.
- Search, sorting, and smooth infinite scrolling.
- Views refresh on their own as downloads finish. No manual reload.
- Select several tracks at once to retry, upgrade, or add them to a playlist.

Track status sorting follows the real download pipeline order rather than alphabetical order, so active work sorts above resolved work, which sorts above unresolved work.

## Content detail

Click any artist, album, or playlist and a rich detail view opens in place, without losing your spot. Navigation stacks, so you can go from an artist to one of their albums to a related artist and back out again.

Each view pulls from several metadata sources at once and streams the sections in as they arrive:

- Artwork, a biography, and factual details.
- For an artist: a discography, top tracks, similar artists, and links to their presence elsewhere.
- For an album or playlist: a full tracklist with live per-track status.
- An overlay showing what you already have in your library.
- Actions to request anything you are missing, individually or in bulk.

When a metadata source is unavailable, Synthseek says so, and says how long it has been unavailable, rather than quietly showing you an incomplete page.

## Playlists

Full playlist management inside your library.

- Create a playlist from tracks you already have.
- Rename and delete your own playlists.
- Add and remove tracks, several at a time.
- Request a playlist from the catalog and Synthseek downloads every track, preserving the original order.

### Playlist import and export

- Import from **JSPF**, **XSPF**, and **Exportify CSV**. The flow is a dry run first, showing you exactly what matched and what did not, then a commit of the selection you approve.
- Export to **JSPF**, round-trippable back into Synthseek.
- Duplicate tracks within an imported playlist are collapsed, with a count of how many were skipped.

### Sync to a media server

Any eligible playlist can be pushed to Plex, one at a time or all at once, from either the requests screen or your library. A background job keeps synced playlists named correctly and topped up with tracks they are missing.

Renames flow both ways. Rename in Synthseek and Plex follows within seconds; rename in Plex and Synthseek picks it up on the next pass.

Currently, playlist sync only ever adds tracks to the remote playlist. It never removes them.

### Play it in the web app

Synthseek plays your library itself. Press play on any track in your library and a player docks at the bottom of the page: play and pause, skip forwards and back, scrub, volume, shuffle, and repeat either the queue or a single track. A full screen view gives you the artwork, and your keyboard's media keys, your lock screen and your car stereo see the track, the artist and the cover through the browser's own media controls.

The queue is the page of tracks you pressed play on, in the order you were looking at them. A track with no file on record does not offer a play button at all, rather than failing when you press it.

Playback is the original file. If your browser cannot decode the format, Synthseek converts it on the fly and scrubbing still works, because the player asks the server to start again from where you dropped the needle.

Your queue is kept for you. Reload the page, come back tomorrow, or open Synthseek somewhere else, and it is there where you left it, paused close to where you stopped. It is the same queue your music apps use, so what you were playing in Symfonium is offered back in the browser, named after the app that left it, and what you queue in the browser is waiting on your phone. The queue and your position travel. Shuffle and repeat are not kept with them, so a tab that opens fresh starts with both off.

Only one place plays at a time. Press play in a second tab, or on another computer, and the sound moves there rather than doubling. The one that stops does not go blank: it keeps showing the same track with the position moving, names the device that has the sound, and its own buttons now drive that device. Pause, skip, scrub, shuffle, repeat and volume all work from any of them, and what you change is reflected everywhere.

Open Synthseek somewhere else while it is playing and it already knows what is on and where, rather than waiting for the next thing to happen. The Synthseek tabs you have open show up under **Where it plays**. Pick one to move the sound there, and pick **This web browser** to bring it back, which resumes where the other one had got to. A tab that has not played anything yet can still be handed the queue, but it waits for you to press play, because a browser will not start audio in a tab you have not touched. A Subsonic app is not in that list at all: its protocol has no way for the server to talk back to it, so Synthseek hands it the queue rather than pretending it can command it, and a music app playing on your phone is the one thing the browser cannot stop.

The heart marks the same favourite your music app marks. Scrobbling is not part of this player yet, so what you play here does not reach Last.fm or ListenBrainz, and it is not counted as now playing.

### Play it in a music app

Synthseek speaks the Subsonic API, so apps built for that ecosystem, Feishin, Symfonium, DSub and others, can browse and play your library directly, without a media server in between. Turn it on in **Settings**, then **General**, then **Connect apps**. It is off until you do.

Each person creates their own credential and pastes it into their app along with the address and their username. A credential is shown once and can be revoked at any time.

The app does what a music app does, and what it does sticks. Favourites you mark there are yours alone and show up marked wherever you look next, in that app or another one. Playlists can be created, renamed, added to and reordered from the app, and they are the same playlists the web app shows. What you played feeds the Recent and Most played lists, and the queue you left behind is offered back when you open a different device. Deleting a playlist from a music app deletes only the playlist, never the music in it, because a swipe is too easy a gesture to lose an album to. Removing the tracks themselves stays in the web app, where it asks first.

Playback is original quality by default. If your app asks for a particular format or caps the bitrate, Synthseek converts on the fly and sends that instead, which is what makes a lossless library usable on a phone or a slow connection. Conversion can be switched off in settings, and it is bounded so a busy server refuses new conversions rather than grinding.

Three limits worth knowing before you rely on it. Only tracks Synthseek imported are offered, so music you added to the library folder by hand is offered once the library scan has found it and identification has worked out which track it is. Only tracks whose file location Synthseek has on record are offered, and it works those out by scanning the library, which happens twice a day and which you can start yourself from the Jobs page, so anything it has not placed yet stays out until it has. And a converted stream cannot be seeked mid-track, so scrubbing works on original-quality playback only.

## Discovery

A dedicated Discover page with a trending hero, browsable genres, an artist spotlight, a leaderboard of what is most represented in your library, and your recent requests.

### Connect your listening history

- **ListenBrainz** provides discovery mixes: collaborative filtering recommendations, weekly exploration, weekly jams, and daily jams. Choose which mixes you want, name them, and optionally have Synthseek request their tracks automatically as they refresh. A mix can be kept as a single playlist that updates in place, rather than creating a new dated playlist every time.
- **Last.fm** surfaces your recent scrobbles and top tracks, with real artwork, and powers similar-artist recommendations across the application.

Discovery integrations are per user. Each member connects their own accounts and gets their own mixes.

## Import your existing library

Connect a library source and bring your existing collection across.

Spotify is supported today. Browse your saved albums, saved tracks, and playlists in a table with bulk selection, pick what you want, and import it. Imported playlists can be kept in sync, so new additions on the source side flow through automatically.

Each member connects their own account and imports into their own library.

## Multi-user

Synthseek is built for more than one person.

- Local accounts, or sign in with Plex.
- Import members straight from your Plex server.
- Three roles: administrator, trusted, and member.
- Administrator-only settings are hidden from everyone else, not merely disabled.
- Requests are scoped to their owner and show who made them.
- Each member has their own profile, their own connected accounts, and their own language preference.
- Optionally require administrator approval before a plain member's requests download anything.

## Interface

- Modern and responsive, with a bottom navigation bar on phones.
- Three themes: Synthseek, Midnight, and Ocean.
- Four languages: English, Español, Deutsch, and Français.
- Live progress everywhere, driven by server-sent events rather than polling.
- A progress dock that follows long-running work such as playlist population, library imports, and media server sync.
- In-app update notifications when a newer version is published, with the patch notes for it.

## AI assistants

Synthseek ships an MCP server, so an assistant such as Claude can search, request, organise, and report on your library in plain language. Around forty tools cover search, downloads, requests, playlists, library, listening history, settings, and operations.

Every connection is scoped to one member. An assistant sees and acts on that member's account and library only, shaped by their role.

See the [AI Assistants page](/ai-assistants).

## Operations

- A jobs section listing every background job relevant to your setup, with what each one does, when it runs next, a run-now button, a progress state while one is running, and a marker on a run that ended badly.
- A log viewer with level filtering, auto-refresh, and export.
- A live health view for each connected service.
- Automatic database backups before any schema change, and, where there is room, a copy-validated upgrade that proves the migration on a copy before touching your live database.
